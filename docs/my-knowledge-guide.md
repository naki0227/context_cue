# My Knowledge入力ガイド

## 目的

My Knowledgeは、AIに人格や回答を代行させる場所ではない。
会話中に自分が忘れたくない事実、経験、判断、確認事項を思い出すための情報源である。

## 最初に入れるとよい情報

### 1. 基本プロフィール

- 呼ばれたい名前
- 現在の所属、役割、担当
- 使用言語、timezone
- 今取り組んでいること
- このツールを使う会話の種類

例:

```md
# 基本プロフィール

- 呼ばれたい名前: User
- 現在の役割: 大学生 / 個人開発者
- 主な活動: Web開発、研究、就職活動
- よく使う場面: 研究ミーティング、1on1、カジュアル面談
```

### 2. 経験・エピソード

事実と自分の解釈を分け、数字の根拠も書く。

```md
# USJでの改善経験

- 状況: 休日の入場ゲートで待ち時間が長かった
- 課題: 案内方法が担当者ごとに異なっていた
- 自分の役割: 混雑状況の観察と案内手順の整理
- 行動: 3パターンの案内文を作り、チームで試した
- 結果: 待ち時間を約15%短縮した
- 根拠: シフト記録と現場計測。概算値
- 学び: 小さく試してから標準化することが重要
- 話してよい範囲: 社名と個人名を除けば可
```

### 3. プロジェクト・研究

- 目的
- 自分の担当
- 現状
- 決定事項
- 未決定事項
- リスク
- 次の行動

### 4. 強み・スキル

抽象語だけでなく、根拠となる具体例を紐付ける。

```md
# 強み

## 仮説検証を続けられる

- 根拠: 個人開発で5回のユーザーテストを実施した
- 成果: 初回完了率を42%から71%へ改善した
- 注意: 数値はテスト参加者14人の範囲
```

### 5. 人・組織

- 相手の役割
- 前回話した内容
- 次に確認したいこと
- 約束したこと

第三者の住所、私用連絡先、評価、健康情報など、会話支援に不要な情報は入れない。

### 6. 自分の価値観・希望

- 大切にしたい働き方
- 得意・不得意
- 意思決定の基準
- キャリアや研究の希望
- まだ確定していないこと

### 7. NG・注意事項

- 話してはいけない秘密
- 数字の確度
- 誇張しやすい表現
- 未確認事項
- セッションで参照させたくない項目

## 入れない方がよい情報

- パスワード、API key、秘密鍵、復旧コード
- マイナンバー、免許証番号、口座・カード情報
- 会話支援に不要な住所、健康、家族情報
- 同意なく取得した第三者の個人情報
- 契約上保存できない社外秘
- 出典や確度を確認できない噂

## おすすめの項目構造

各項目は次の形にそろえる。

```md
# タイトル

- 種類: profile | experience | skill | project | person | decision | todo
- 更新日: YYYY-MM-DD
- 出典: 本人記憶 | 文書名 | セッション名
- 確度: 確認済み | 概算 | 未確認
- 機密度: 一般 | 個人 | 機密
- 利用場面: 会議 | 面談 | 1on1 | GD | その他
- 内容:
- 根拠:
- 次に確認すること:
- 話してよい範囲:
```

## AIに整理してもらうためのプロンプト

このpromptは、ローカルLLMまたは利用者が送信先を確認したAIへ貼り付ける。
クラウドAIへ送る場合は、個人名、社名、秘密情報を先に匿名化する。

```txt
あなたは「会話中に本人が事実を思い出すための個人ナレッジ」を整理する編集者です。
回答代行や人物像の捏造はせず、入力された事実だけを整理してください。

目的:
- 会議、面談、1on1、グループディスカッション中に短時間で参照できる形にする
- 自分の経験、判断、根拠、未確認事項を区別する
- Context CueのMy KnowledgeへMarkdownとして追加できる形にする

必須ルール:
1. 入力にない事実、数字、固有名詞を補わない
2. 不明点は「未確認」と書く
3. 推測は事実と分けて「本人の解釈」と明記する
4. パスワード、API key、秘密鍵、口座、本人確認番号は出力しない
5. 第三者の不要な個人情報は削除または匿名化する
6. 完成された回答文や面接の丸暗記文は作らない
7. 1項目を短くし、検索に使える具体語を残す
8. 重複する内容は統合する
9. 数字には出典または確度を付ける
10. 情報が不足する場合、最後に最大5個だけ確認質問を出す

分類:
- profile: 基本プロフィール、現在の役割、希望
- experience: 状況、課題、役割、行動、結果、学び
- skill: スキルと根拠
- project: 目的、担当、現状、決定、課題、次の行動
- person: 相手の役割、前回内容、次回確認
- decision: 決定事項、理由、影響
- todo: 次の行動、期限、担当
- caution: NG、未確認、話してよい範囲

出力形式:
# 整理結果

## [分類] 項目タイトル
- 更新日:
- 出典:
- 確度:
- 機密度:
- 利用場面:
- 事実:
- 自分の役割・判断:
- 根拠・数字:
- 学び・次の行動:
- 話してよい範囲:
- 検索キーワード:

# 重複・矛盾
- なければ「なし」

# 除外したセンシティブ情報
- 内容そのものは再掲せず、種類だけを書く

# 確認質問
- 最大5個

これから整理対象を渡します。
--- 入力開始 ---
[ここに自分のメモを貼る]
--- 入力終了 ---
```

## アプリ内オンボーディング案

初回起動では空のダッシュボードを直接見せず、次の順番で案内する。

1. ローカル保存と外部送信なしを説明する
2. 呼ばれたい名前と利用場面だけ入力する
3. 入力例から1つ選ぶ
4. テンプレートへ事実を入力する
5. AI整理前に「送信される内容」をpreviewする
6. AI整理結果を差分表示し、ユーザーが承認して保存する
7. 機密度と利用セッションを選ぶ

最初から大量入力を求めない。「基本プロフィール」「経験1件」「確認したいこと1件」
の3項目で開始し、利用後に不足カテゴリを提案する。

## AI整理機能の安全要件

- デフォルトはローカルLLMだけを使用する
- AI入力へ含める項目をユーザーが確認できる
- 原文を保持し、AI整理結果との差分を表示する
- 自動上書きせず、承認後に保存する
- 各項目へ出典、確度、更新日、機密度を持たせる
- 「このセッションでは参照しない」を選べる
- AIが追加した内容ではなく、整理・短文化した内容だけを採用する
