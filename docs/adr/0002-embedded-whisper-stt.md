# ADR 0002: 組み込みWhisper STT

## 状態

採用

## 背景

How to Talkは会話内容を外部へ送信せず、一般的なPCでリアルタイムに日本語を文字起こしする必要がある。利用者へ別のSTTサーバー構築を要求しないことも重要である。

## 課題

- macOS、Windows、Linuxのマイク入力を同じ境界で扱う。
- 初回モデル取得を検証・中止可能にする。
- 無音区間による無駄な推論とWhisperの幻聴を抑える。
- UI、音声入力、推論、セッション処理を密結合させない。

## 選択肢

1. 外部STT APIへ音声を送信する。
2. whisper.cppサーバーを別プロセスとして導入してもらう。
3. `cpal`と`whisper-rs`をデスクトップアプリへ組み込む。

## 採用した案

`cpal`でマイク入力を取得し、16kHz monoへ変換する。4秒ごとに簡易VADを通し、発話区間だけを`whisper-rs`経由のwhisper.cppで日本語文字起こしする。

モデルは公式`ggerganov/whisper.cpp`の`ggml-base-q5_1.bin`を利用し、SHA-1と最小サイズを検証してから`0600`で保存する。

## 採用理由

- 会話音声を端末外へ出さない。
- 利用者が別STTサービスを起動する必要がない。
- 約59MBのモデルで初回導入とメモリ負荷を抑えられる。
- repository traitにより将来別モデルへ差し替えられる。

## メリット

- マイク、モデル、文字起こしをアプリ内で完結できる。
- モデル取得の進捗表示と中止ができる。
- VADにより無音推論と不要なCPU負荷を減らせる。
- モデルコンテキストを再利用し、区間ごとの再読込を避けられる。

## デメリット

- base量子化モデルの精度は大型モデルより低い。
- 話者分離とシステム音声入力は含まれない。
- ネイティブビルドにCMake、Clang、LinuxではALSA開発パッケージが必要。
- 初回のOSマイク権限確認が必要。

## 実装方針

- モデル未取得でもセッション自体は開始可能にする。
- 音声認識失敗は次区間から再試行し、セッションを停止しない。
- 生音声は保存しない。
- 推論は1本ずつ直列化し、モデルコンテキストを再利用する。
- モデル取得先とchecksumはコード側で固定する。

## 将来的な見直し条件

- 実会話で日本語精度が受け入れ基準を満たさないとき。
- 低メモリ端末でOllamaとの同時利用が難しいとき。
- speaker diarizationまたはシステム音声入力を実装するとき。
- 公式モデルの配布先またはchecksumが変更されたとき。
