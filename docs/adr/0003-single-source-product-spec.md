# ADR 0003: 製品仕様書を単一の正本から配布する

## 背景

製品仕様が要件定義、設計書、TODO、画面実装へ分散しており、利用者と開発者が現在の仕様を一か所で確認できなかった。インストール後のアプリはリポジトリ内Markdownを直接読めない。

## 課題

- アプリ内、CLI、GitHubで同じ仕様を読める必要がある
- 同じ本文を複数ファイルで手動管理したくない
- アプリはオフラインで動作する必要がある
- Markdown HTMLの直接挿入は避けたい

## 選択肢

1. アプリとCLIへ別々に仕様文を埋め込む
2. 実行時にGitHubから仕様書を取得する
3. `docs/SPEC.md`を正本とし、CLIは直接読み、アプリ用データを生成する

## 採用した案

選択肢3を採用する。

## 採用理由

GitHubとCLIは人が読みやすいMarkdownをそのまま利用できる。デスクトップ版は生成データをバンドルするためオフラインで閲覧できる。CIでハッシュと生成結果を検査し、二重管理による不一致を防げる。

## メリット

- 仕様本文の正本が一つになる
- アプリをオフラインで利用できる
- CLIから章単位・JSON形式で取得できる
- HTML直接挿入を使わず安全に表示できる
- 仕様更新漏れをCIで検出できる

## デメリット

- 仕様変更時に生成コマンドが必要
- Markdown表現のすべてをアプリ内表示が対応するわけではない
- 生成ファイルをリポジトリで管理する必要がある

## 将来的な見直し条件

公開ドキュメントサイトを追加する場合、同じ正本からサイト、アプリ、CLIを生成する構成へ拡張する。多言語化する場合は言語別正本と翻訳同期ルールを別ADRで決める。
