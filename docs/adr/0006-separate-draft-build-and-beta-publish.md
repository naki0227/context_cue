# ADR 0006: Draft生成とベータ公開を分離する

## 背景

公開成果物は開発元と分離したリポジトリへGitHub Actionsから転送している。
公開側アカウントを開発端末へログインさせず、実機確認前の誤公開も防ぐ必要がある。

## 課題

- Draft作成成功だけで未検証成果物を公開しない
- 公開操作に対象tagと人による明示確認を要求する
- 公開側の認証情報を端末へ保存しない
- 公開前に最低限の成果物と注意文を自動検査する

## 選択肢

1. Release build成功時に自動公開する
2. 公開側アカウントでGitHubへログインし、手動公開する
3. 元リポジトリにDraft生成と分離した手動公開workflowを設ける

## 採用した案

選択肢3を採用する。公開workflowは`workflow_dispatch`だけで起動し、tag、
実機確認checkbox、`publish <tag>`の確認文を要求する。公開前にDraft・Pre-release・
ベータ注意文、3 OSのアプリ成果物、4件以上のSHA-256を検査する。

## 採用理由

登録済みRepository Secretを利用して認証情報を端末から分離しつつ、
ビルドと公開の責務を分けられる。自動検査と人の明示確認を組み合わせることで、
単純なworkflow再実行による誤公開を防ぎやすい。

## メリット

- 公開側アカウントのローカルログインが不要
- 実機確認前の自動公開を防げる
- 成果物不足やベータ注意文の欠落時はDraftを維持できる
- 公開操作と結果がActions履歴に残る

## デメリット

- 公開時に別workflowを1回実行する必要がある
- 実機確認の内容自体はcheckboxだけでは自動証明できない
- GitHub ActionsまたはRepository Secret障害時は公開できない

## 将来的な見直し条件

署名・公証、SBOM、自動Updater、GitHub Environmentの承認者設定を導入した場合に、
製品版向けの公開条件と承認フローを別途見直す。
